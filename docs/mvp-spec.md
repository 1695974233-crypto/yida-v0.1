# 最小 MVP 规格

## MVP 目标

验证用户是否愿意建立一个最小个人衣柜，并把推荐真正穿出门。

MVP 不以用户量、内容数量或 AI 炫技为目标。核心验证问题只有三个：

1. 用户愿不愿意录入衣服？
2. 系统推荐是否会被采纳？
3. 用户是否会持续回来使用？

## 必须完成的用户路径

1. 用户打开易搭。
2. 允许定位或手动选择城市。
3. 选择风格偏好。
4. 从虚拟衣柜选择相似单品，或上传真实衣服。
5. 选择场景、跳过场景或用一句话描述要求。
6. 获得三套不同方向的搭配。
7. 收藏、点踩或确认“今天穿这套”。
8. 将衣服放入脏衣篓。
9. 再次推荐时不出现不可用衣服。
10. 第二天回来仍能看到衣柜和历史。

## MVP 页面

### 1. 首次使用

- 定位授权或城市选择。
- 风格偏好。
- 温度敏感程度。
- 常用场景。
- 身高、体重、肤色等设置为可选，不作为使用门槛。

### 2. 虚拟衣柜

- 展示基础单品。
- 用户选择“我有类似款”。
- 立即生成第一批推荐。

### 3. 我的衣柜

- 查看和筛选衣物。
- 上传、修改和删除。
- 放入脏衣篓或恢复。
- 区分虚拟单品和真实衣服。

### 4. 今日推荐

- 展示天气。
- 场景可选。
- 对话需求入口。
- 三套搭配及推荐理由。
- 单品替换。
- 喜欢、不喜欢、收藏和已穿。

### 5. 穿搭助手

- 保存当天会话。
- 理解用户临时要求。
- 将要求转换为推荐限制。
- 支持清除当前要求。

### 6. 我的

- 个人偏好。
- 收藏穿搭。
- 30 天历史。
- 隐私与数据删除。

## v0.1 推荐规则

v0.1 使用确定性规则，而不是训练机器学习模型。

```text
读取当前衣柜
→ 排除脏衣服
→ 排除聊天中明确不要的衣服
→ 根据温度筛选厚度
→ 根据场景计算匹配度
→ 根据用户风格加分
→ 根据颜色和雨天适配加分
→ 组合上衣、下装、外套和鞋
→ 返回得分最高且彼此不同的三套
```

评分参考：

| 维度 | 参考权重 |
|---|---:|
| 天气和舒适度 | 25% |
| 场景匹配 | 25% |
| 用户风格偏好 | 20% |
| 色彩与版型协调 | 15% |
| 历史反馈 | 10% |
| 新鲜感与衣物利用率 | 5% |

## 反馈事件

- `recommendation_exposed`：推荐被展示。
- `recommendation_opened`：用户展开详情。
- `liked`：喜欢。
- `disliked`：不适合。
- `collected`：收藏。
- `item_replaced`：替换单品。
- `outfit_worn`：确认穿着。
- `outfit_skipped`：跳过。
- `shared`：分享。
- `try_on_generated`：生成试穿。

最有价值的反馈是 `outfit_worn`，它比点赞更接近真实使用结果。

## v0.1 验收标准

- 用户能建立至少包含上衣、下装和鞋子的衣柜。
- 用户能选择或跳过场景。
- 用户能用自然语言表达常见穿搭要求。
- 推荐只使用当前可用衣服。
- 脏衣篓中的衣服不参与推荐。
- 修改衣柜后推荐发生变化。
- 关键操作刷新后仍保留。
- 用户能确认“今天穿这套”。

## MVP 暂不包含

- 社区、评论和关注。
- 自研大模型或虚拟试穿模型。
- 无限穿搭信息流。
- 复杂机器学习排序。
- 自动抓取未经授权的平台内容。
- 尺码和真实合身承诺。
